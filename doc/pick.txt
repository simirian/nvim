*simi.pick*    Dynamic popup selection with fuzzy matching.

                                  by simirian

Overrides `vim.ui.select()` with a popup menu which provides fuzzy matching
and a string input. Also adds a variety of prebuilt pickers which can be
invoked through the `:Pick` command.

==============================================================================
Pick Command                                                        *:Pick*

The `:Pick` command provided by this plugin gives access to the complete
functionality contained within. The command accepts one argument, which is the
name of the picker which is invoked. It will be one of the pickers listed in
|pick-pickers|.

==============================================================================
Keymaps                                                         *pick-keymaps*

The pick keymaps all start with `<leader>f` in an effort to make them easy to
use. The mnemonic for this keymap is "find", as in you are finding particular
entries from among a list. Every keymap is then followed by a mnemonic letter
(usually the first letter of the name) which invokes the picker.

While in a picker input window, the following keymaps will be overwritten.

map     modes   windows     action ~
<cr>    in      i           confirm selection
<esc>   n       ip          close the picker
<c-6>   n       ip          switch between input and preview windows
<c-n>   in      i           select the next item in the list
<c-p>   in      i           select the previous item in the list
<c-q>   in      i           send the items to the quickfix list

The modes in the table should be read as `:map` prefixes, see |map-modes|. The
window column is a list of boolean flags which are present when the keymap
works in the inpute (`i`) and preview (`p`) windows.

Sending items to the quickfix list only works for pickers which are
quickfix-compatible. Among the default pickers, only the help picker is not
quickfix-compatible, though the quickfix list isn't particularly useful for
those pickers other than te grep picker.

==============================================================================
Pickers                                                         *pick-pickers*

Several pickers are available for use through the |pick-keymaps| and the
`:Pick` command. They are shown in the table below, where "name" is the name
by which they can be invoked with the command, "keymap" is the keymap which
invokes the default picker, "input method" is the type of input used to select
entries from the list, and "picks over" is a description of the items which
will be available in the list.

name        keymap  input method    picks over ~
files       ff      fuzzy           all child files except those in `.git/`
gitfiles    fg      fuzzy           files that git knows about
help        fh      fuzzy           help tags in rtp `doc/` directories
grep        fs      raw ripgrep     grep search in the current directory
buffers     fb      fuzzy           buffer names in `:ls`

The following pickers are planned for future releases:

- quickfix list entries
- location list entries
- character selector (emoji, unicode, nerdfonts)

==============================================================================
Fuzzy Finding                                                   *pick-fuzz*

Fizzy finding using this module has special input semantics based on prefixes
to search terms. A leading space at the start of a fuzzy search query will be
ignored and force fuzzy matching with the rest of the string, so if you want
to search with a prefix character you are able to.

Starting a query with one of an apostrophe "'", a caret "^", or a dollar sign
"$" will search for the following |lua-pattern| in, at the start of, or at the
end of each item in the list. Further prefixing with a bang "!" will negate
the pattern matching, so only entries which do not match will be shown and
selectable. The prefixes are summarised in the table below.

prefix      meaning ~
'           the query is a lua pattern
!'          the query is a lua pattern which is not in the target
^           the query is a lua pattern that the target starts with
!^          the query is a lua pattern that the target does not start with
$           the query is a lua pattern that the target ends with
!$          the query is a lua pattern that the target does not end with
<space>     the query is a fuzzy-matching pattern

In all cases, the entire prefix is stripped from the start of the query when
the query is used for matching. This means that " 'spe" will do a fuzzy search
for the term "'spe", which will probably find the 'spell' option in the help
picker. If a query starts with a bang but does not match one of the prefixes
above, the bang is included in a fuzzy match over the entire input. This means
that "!file" will search over that entire term.

Fuzzy matching uses the built-in `matchfuzzy()` function, which is based on
https://github.com/junegunn/fzf. It's a pretty generic fuzzy-matching
algorithm, and it's way faster because it's implemented in c instead of lua.
If matching is blocking for longer than it should, open a PR/issue and we'll
work on it.

==============================================================================
API                                                                 *pick-api*

This plugin provides a public API which can be accessed by requiring the pick
module:
>lua
        local pick = require("pick")
<

The module allows programmatic access to activating the built-in pickers by
their name, as well as invoking custom pickers with the |pick.pick()|
function.

CUSTOM PICKERS                                              *custom-pickers*

Custom pickers can be created using the `pick()` function. It expects a single
table argument, which is essentially a strategy for running the picker. It
expects a list of items or a function to generate them asynchronously. The
sort function is asynchronous and given the generated list and the user's
prompt, and is expected to filter and sort the options to best fit the user's
prompt. The disply function is used to convert the items to string, and the
toquickfix function is used to convert the items to quickfix items if that's
relevant behavior. The confirm function is called when the user confirms their
selection.

pick({args})                                                    *pick.pick()*
    Invokes a picker with the given arguments. This will open the picker
    windows and run the list and sort functions.

    If the mandatory keys in this function's arguments are not supplied, they
    will be replaced with trivial default implementations instead of raising
    errors.

    Example: >lua
        require("pick").pick({
          list = {"apples", "oranges", "bannanas"},
          sort = function(items, prompt)
            return vim.fn.matchfuzzy(items, prompt)
          end,
          confirm = function(item)
            print("The user chose " .. item .. "!")
          end,
        })
<

    Parameters: ~
      • {args}  (|Pick.Args|) Table of keyword arguments.

*Pick.Args*

    Fields: ~
      • {list}         (`any[] | fun(): any[]`, default: empty) The initial
                       list of items, supplied to the sorter. When this is an
                       array, it is given to the sorter verbatim, when this is
                       a function, it is called in an async context and its
                       output is given to the sorter once it's done. See
                       |async-context|

      • {sort}         (`fun(items: any[], prompt: string): any[]`, default: return verbatim)
                       Function used to sort the items based on the user's
                       prompt. This function returns the list of items which
                       the user is shown. This function does not need to
                       return items in the same form as they were given to it,
                       which can be useful if you want to display sort scores
                       or other sorting data. The output items are given to
                       all other functions which are called in the picker
                       pipeline.

                       This function is called on every text change, so it
                       should be fast or async (it is called in an async
                       context). See |async-context|

      • {display}?     (`fun(item: any, idx: integer): string`, default: tostring)
                       Function used to convert non-stirng items to strings
                       which can be displayed in a buffer. Each item must be
                       converted into a single-line string. If the items are
                       already strings, this may be nil, it may not be nil in
                       any other case.

      • {preview}?     (`fun(item: any, idx: integer, winid: integer)`, default: nil)
                       This function is called every time the user's selection
                       changes or when the input changes, so long as the sort
                       function actually returned any items. This function
                       should set the contents of the the given window to a
                       preview of the currently selected item. The window
                       is pre-populated with an empty buffer which can freely
                       be modified, e.g. fia |nvim_buf_set_lines()|

                       If this argument is not supplied or is nil, then the
                       preview window will not be opened. The preview window
                       will be shon if and only if this argument is not nil.

                       Example: >lua
                       -- a simplified version of the default file preview
                       preview = function(item, _, winid)
                         vim.api.nvim_win_call(winid, function()
                           vim.cmd.edit(item)
                         end)
                       end
<

      • {toquickfix}?  (`fun(item: any, idx: integer): vim.quickfix.entry`, default: nil)
                       Converts a list item to a quickfix item. The output to
                       this function is given directly to |setqflist()|. This
                       argument is optional for a reason, in many cases it
                       doesn't make sense to send items to a quickfix list.

                       The <c-q> keymap will only work if this function is not
                       nil. If it is nil, then they keymap will do nothing.

      • {confirm}      (`fun(item: any, idx: integer)`, default: nothing) This
                       function is called when the user confirms their
                       selection, e.g. by pressing <cr> with the picker open.
                       This is called AFTER the picker closes and the user is
                       returned to their last non-picker window. Defaults to
                       doing nothing.

      • {cancel}       (`fun()`, default: nothing) This function is called
                       when the picker is closed through ANY means which don't
                       end up calling confirm. This is especially useful for
                       cleaning up your own async routines (though you should
                       be using the asyc context provided) and for cleaning up
                       help buffers. This will be called after the picker
                       itself is closed.

cancel()                                                    *pick.cancel()*
    Cancels the currently running picker. This will close the active windows,
    end any library-managed async routines, then call the cancel function
    which was set during the invocation of the picker.

    Example: >lua
        local pick = require("pick")
        -- open the picker
        pick.pick({
          list = {"apples", "oranges", "bannanas"},
          sort = function(items, prompt)
            return vim.fn.matchfuzzy(items, prompt)
          end,
          confirm = function(item)
            print("The user chose " .. item .. "!")
          end,
        })
        -- then immediately close it
        pick.cancel()
<
